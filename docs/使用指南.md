# Dufs GUI

基于 [dufs](https://github.com/sigoden/dufs) 的 Windows 桌面封装：**先配置，再开启**。
Python + tkinter 编写，深色界面，dufs.exe 内置打包，双击即用。

## 一、最快上手

```bat
build_debug.bat    :: 第一次先跑这个：环境体检 + 控制台版 + 自检，看得见报错
build.bat          :: 确认无误后打正式版，产出单个 dist\DufsGui.exe
```

两个脚本都会自动下载 dufs.exe（直连 GitHub，失败自动切镜像）、自动装 PyInstaller（腾讯镜像）。

想先看看界面、不打包：把 `bin\dufs.exe` 放好后 `python main.py`。

> GitHub 实在下不动时：手动打开 https://github.com/sigoden/dufs/releases
> 下载 `dufs-vX.Y.Z-x86_64-pc-windows-msvc.zip`，把 `dufs.exe` 放进 `bin\`，再双击 `build.bat`（它会跳过下载）。
> 也可以在软件里「高级设置 → dufs 程序 → 更换…」手动指定。

## 二、打包与排错

### 环境要求（决定成败）

| 项 | 要求 | 为什么 |
|---|---|---|
| Python | **3.12.x（python.org 官方安装包）** | 官方 CPython 的 Tcl/Tk 布局最标准 |
| 不要用 | conda / Miniconda / 嵌入式版 / Microsoft Store 版 | 这些版本的 tcl/tk 路径不一致，是"闪退"头号原因 |
| 避开 | Python **3.13.0** | 该版本 Windows venv 下有 tkinter 初始化缺陷（`Can't find a usable init.tcl`），CPython issue #125235、PyInstaller #8820；用 3.13.1+ 或 3.12.x |
| 路径 | 纯英文，如 `C:\build\dufs-gui` | 中文/全角路径会让 PyInstaller 引导程序出问题 |

### 三个开关

```bat
set DUFS_GUI_MODE=onefile        :: 默认，单个 exe
set DUFS_GUI_MODE=onedir         :: dist\DufsGui\ 目录，启动更快、杀软误报显著更低
set DUFS_GUI_CONSOLE=1           :: 控制台版（产物名带 -debug），诊断闪退用
set DUFS_GUI_COLLECT_TK=1        :: 强制 --collect-all tkinter，仅当 Tcl/Tk 缺失时
```

### 推荐流程

`build.bat` 和 `build_debug.bat` 都产出**单文件 exe**：

| 脚本 | 产物 | 控制台 |
|---|---|---|
| `build_debug.bat` | `dist\DufsGui-debug.exe`（单个文件） | 开，报错可见 |
| `build.bat` | `dist\DufsGui.exe`（单个文件） | 关，正式版 |

**第一次务必走 `build_debug.bat`**：环境体检（Python 版本 / tkinter 可用性 /
路径）→ 单文件 + 控制台打包 → 跑 `--selftest` → 运行留错 → 打印 crash.log。
确认无误后 `build.bat` 出正式版。

想要 onedir（目录形态，杀软误报更低）就手动改一行：
`set DUFS_GUI_MODE=onedir`（产物变成 `dist\DufsGui\` 目录）。

> 所有 bat 均为**纯 ASCII 英文**。Windows 中文 cmd 默认按 GBK 读批处理，
> UTF-8 编码的中文 bat 会被解成乱码并被当成命令执行，满屏"不是内部或外部命令"。

### 共享失败怎么查

启动失败时会**直接弹出 dufs 的真实输出**，不用去翻日志。

另外加了两层保护：

1. **进程秒退立即判定失败**：不再白等 8 秒超时（`wait_ready` 同时监测进程存活）
2. **自定义皮肤自动降级**：若失败时带了 `--assets`，会自动去掉它重试一次。
   也就是**网页皮肤永远不会挡住共享本身**——真出问题会自动关掉并提示你。

常见原因：端口被占用（会提示换端口）、共享目录不存在、
TLS 证书/私钥路径不成对、dufs 版本过旧不支持某个参数。

### 闪退排查

`console=False` 下未捕获异常会静默退出，双击就是一闪而过。**先让错误看得见**，别猜。

1. 双击 **`build_debug.bat`** —— 它会把 exe 的**全部输出重定向到文件再回显**，
   所以哪怕程序一闪而过也留得下；每段之间还会 pause，双击也不会关窗
2. 若已打包好、只想看运行时报错，用 **`run_debug.bat`**（可把 exe 直接拖到它上面）
3. 或读 `%LOCALAPPDATA%\DufsGui\crash.log`（内置 `core/crashlog.py` 兜底，附环境快照）

| 报错 | 原因 | 处理 |
|---|---|---|
| `NameError: name 'OS' is not defined` | spec 用了不存在的全局变量 | **已修复**。只有 `DISTPATH/HOMEPATH/SPEC/SPECPATH/specnm/workpath/WARNFILE`，判断系统请 `import os` |
| `Can't find a usable init.tcl` / `No module named '_tkinter'` / `_tk_data` 缺失 | Tcl/Tk 没收集 | 换官方 CPython；或 `set DUFS_GUI_COLLECT_TK=1` 重打 |
| `Theme 'clam' not found`、ttk 样式失效 | tcl8.6/tk8.6 的 ttk 主题文件缺失 | 同上，`DUFS_GUI_COLLECT_TK=1` |
| dufs 启动失败、无输出 | 子进程继承了 bootloader 的 DLL 搜索路径 | **已修复**：`Popen` 前调用 `SetDllDirectoryW(None)` 并从 PATH 剔除 `_MEIPASS`（官方 "Launching External Programs" 章节要求） |
| 无任何报错、窗口秒退 | 杀软拦截 | 给 `dist` 加白名单；或改用 `DUFS_GUI_MODE=onedir`（不往 TEMP 释放，误报低得多） |
| 打包期路径类报错 | 路径含中文 | 挪到纯英文路径 |
| 改了代码但行为没变 | 双击了旧 exe | 只双击 `dist\` 下**新生成**的，打包前关掉正在运行的旧实例 |

### onefile 与 onedir 怎么选

| | onefile | onedir |
|---|---|---|
| 交付形态 | 单个 exe | 一个目录（可用 Inno Setup/NSIS 打包成安装器） |
| 启动 | 每次解压到 `%TEMP%\_MEI*`，首次 1-3 秒 | 直接运行，快 |
| 杀软误报 | **高**（往临时目录释放可执行文件的行为本身可疑，且本项目还会释放并启动 dufs.exe） | 低得多 |
| 体积 | 单文件 25-35 MB | 目录总计相近 |

结论：内网受控用 onefile 没问题；要分发给别人，**优先 onedir 再套安装器**。

### 已修复的打包缺陷

- **`OS` 未定义**：spec 里 `OS` 不是 PyInstaller 全局变量，实测（6.22）报 `NameError` 直接中断打包。改为 `import os` + `os.name == "nt"`
- **子进程 DLL 搜索路径污染**：Windows bootloader 的 `SetDllDirectoryW` 会被子进程继承，外部 dufs.exe 可能加载到不兼容 DLL。已按官方要求清理
- **缺 dufs 就中断**：降级为警告，允许打出不带 dufs 的产物，启动后手动指定
- **崩溃不留痕**：新增 `core/crashlog.py`，接管 `sys.excepthook`、线程异常、tkinter 回调异常

## 三、界面与网页皮肤

### 桌面端（tkinter）

- **复选框勾选**：clam 主题下**对勾是硬编码深色**，改不了颜色——之前选中态
  用了深色底，深底 + 深勾 = 完全看不见。现在选中时方框填成高亮 accent 色，
  深色对勾落在亮底上就清晰了；同时把 `indicatordiameter` 放大到 16。
  （结论来自 Stack Overflow / Tcler's Wiki：Windows 与 OSX 默认主题的对勾是
  图片，改不了，必须换 clam 这类 Tk 绘制主题才可控。）
- **下拉框配色**：ttk.Combobox 的下拉列表是**原生 tk.Listbox，不是 ttk 控件**，
  `ttk.Style` 对它完全无效。只能用 option database，且**大小写敏感**
  —— `selectBackground` / `selectForeground` 的 B、F 必须大写，写成
  `selectbackground` 会静默失效（Tcler's Wiki / Stack Overflow 双源印证）。
  另外下拉箭头的 `arrowcolor` 默认黑色，叠在深色背景上根本看不见。
  现已全部修正，并在切换主题时用 `tk.eval` 直接刷新已存在的下拉列表
  （option_add 只在 widget 创建前可靠生效，运行时切主题属于"之后"）。
- **高级设置弹窗不再被裁切**：**不写死尺寸，按内容实测高度**。
  建完所有控件后读 `outer.winfo_reqheight()`，加上下留白再套 `geometry`，
  所以以后新增任何一行都不会再被切掉（之前写死 620×560，加了「网页皮肤目录」
  两行后就撑破了）。
  另外包了一层 **Canvas + 滚动条**：屏幕高度不够时改为滚动，而不是截断内容。
  鼠标滚轮绑到了每个子控件（只绑 Canvas 的话，指针停在输入框上就滚不动）。
  位置居中于主窗口，并做**多显示器钳制**：先 `withdraw` 再定位再 `deiconify`
  （否则会先闪一下默认位置），按 `EnumDisplayMonitors` 逐块屏比较重叠面积，
  保证不会跑到两屏之间的缝里或屏幕外。
- **移除「上传到共享目录」面板**：网页端拖拽上传已经够用，GUI 里再做一套重复。

### 网页端皮肤（重要：曾导致共享失败）

#### 根因：dufs 启动时硬性要求 `--assets` 目录里必须有 index.html

dufs 源码 `src/args.rs`：

```rust
fn sanitize_assets_path(path: P) -> Result<PathBuf> {
    let path = Self::sanitize_path(path)?;
    if !path.join("index.html").exists() {
        bail!("Path {} doesn't contains index.html", path.display());
    }
    Ok(path)
}
```

也就是说：**"缺的文件运行时回退内置"只对 index.css / index.js / favicon.ico 成立，
index.html 缺失会直接 `bail!` 拒绝启动**。

上一版只放了 `index.css`，所以 dufs 起不来——这就是你看到"自定义网页皮肤导致
dufs 无法启动"的原因。已修复。

#### 现在的做法：自带完整前端

`assets/` 下三个文件齐全：**index.html + index.css + index.js**，全部自研，
**不加载也不依赖 dufs 内置的任何前端文件**，因此不存在版本兼容问题。

- 数据来自 dufs 注入的 `__INDEX_DATA__`（base64 JSON）
- 资源路径用 `__ASSETS_PREFIX__`
- 功能：面包屑、排序、搜索、拖拽上传（带进度）、下载、删除、新建文件夹、
  打包下载，按 dufs 的权限开关自动显隐

#### 开关在哪

主界面「网页端能力」区最后一项 **「网页美化界面」**。**默认关闭**——
宁可样式朴素，也不能让皮肤挡住共享本身。

想用第三方皮肤（官方 README 推荐，成熟且经过验证）：

1. 下载如 [dufs-material-assets](https://github.com/TransparentLC/dufs-material-assets) 的 release 包
2. 解压到任意目录
3. 高级设置 → 「网页皮肤目录」指向它

目录必须含 `index.html`，选择时会校验。

#### 三重保险

1. 启动前校验：皮肤目录不含 `index.html` 时直接拦截并提示
2. 命令行生成时再次校验，不合法就不加 `--assets`
3. 启动失败且带 `--assets` 时，自动去掉重试一次

## 四、界面能配什么

| 分区 | 项目 | 对应 dufs 参数 |
|---|---|---|
| 共享目录 | 目录或单个文件 | `serve-path` |
| 网络与接口 | 监听地址、端口、路径前缀 | `-b` `-p` `--path-prefix` |
| 网页端能力 | 上传 / 删除 / 搜索 / 打包下载 / 符号链接 / CORS | `--allow-*` `--enable-cors` |
| 高级设置 | 隐藏规则、渲染模式、日志文件、HTTPS 证书、dufs 程序位置 | `--hidden` `--render-*` `--log-file` `--tls-*` |

**路径前缀**：填 `files` 后访问地址变成 `http://ip:5000/files/`，留空则用 `/`。

**删除开关**：勾选后网页端出现删除按钮并可删除文件/文件夹；不勾选即为纯只读（仍可下载）。

**配置方案**：可以把「目录 + 端口 + 能力」存成多套方案随时切换，满足"不同目录分别共享"的场景
（dufs 单实例只能共享一个根路径，多目录同时共享 = 开多个实例）。

删除（已移除）

右侧「上传到共享目录」：选文件 → 填存放子目录（留空即根目录）→ 开始上传。
进度条按**全部文件的总字节数**实时刷新，可随时取消。
实现方式是 GUI 侧直接对 dufs 发起 HTTP `PUT`（标准库 `http.client`，无第三方依赖），
目录不存在时会自动 `MKCOL` 逐级创建。

> 前提：需要勾选「允许上传」，且服务处于运行状态。

## 五、深色模式

默认深色，右上角按钮一键切换浅色。标题栏在 Windows 10/11 上也会跟随深色。
主题与配置保存在 `%APPDATA%\DufsGui\config.json`。

## 六、安全默认值

- 监听默认 `127.0.0.1`（仅本机），要局域网共享请手动改成 `0.0.0.0` 或具体网卡 IP
- 开启符号链接会二次确认（可能暴露共享目录之外的文件）
- 关闭窗口时若服务在运行会二次确认并自动停止子进程

## 七、目录结构

```
main.py               入口
app.py                GUI 主界面
core/config.py        配置模型、命令行生成、校验、持久化
core/server.py        dufs 子进程管理与日志采集
core/dufsbin.py       dufs 二进制定位与释放（支持 PyInstaller 内置）
core/netutil.py       本机 IP、端口占用检测
core/theme.py         深色/浅色主题
core/crashlog.py      崩溃兜底与自检（闪退排查用）
core/app_state.py     全局深色状态（避免模块循环依赖）
core/winpos.py        弹窗定位（多显示器钳制）
assets/index.css      dufs 网页皮肤（只换 CSS，HTML/JS 用内置）
tools/fetch_dufs.py   下载官方 dufs 二进制
tools/embed_dufs.py   把 dufs 内嵌为 base64 源码（可选）
build_debug.bat       诊断版打包：体检+抓输出，闪退时先跑这个
run_debug.bat         只运行已有 exe 并抓取全部输出（可拖 exe 上去）
tests/test_core.py    核心逻辑单测（python -m unittest discover -s tests）
```

## 八、已知限制

- WebDAV、账号密码管理未做 GUI 封装（dufs 本身支持，需要可自行加参数）
- 单实例只服务一个根路径
- `.exe` 需在 Windows 上执行 PyInstaller 打包
- 开发环境为 Linux 且无 tkinter，**GUI 窗口的实际渲染未做过端到端验证**；
  已验证的是：spec 能打包通过、内置二进制能正确释放并保留可执行权限、
  崩溃兜底能落盘、自检能输出环境快照。首次在 Windows 跑请先看 `build_debug.bat` 的输出
